# Paper Experiment Protocol

This protocol defines the paper-ready experiment tables produced by the current mock-backed system.

## Required Tables

### Baseline Comparison

Generated by:

```bash
python -m optiresearch.cli run-baselines --objective "Design depth-invariant and spectrally discriminative EDOF-HSI encoder"
```

Columns:

- Encoder
- Run ID
- Depth Similarity
- Spectral Separability
- MTF
- Energy
- Joint

Output:

- `workspace/baselines/baseline_comparison.json`
- `workspace/baselines/baseline_comparison.md`

### Memory Ablation

Generated by:

```bash
python -m optiresearch.cli run-benchmark --name opti-memory --mode full_rmos
```

Columns:

- Mode
- Plan Hit
- Evidence Complete
- Unsupported Claim Rate
- Trigger Precision
- Total Score

Output:

- `workspace/benchmarks/opti_memory_bench_report.json`
- `workspace/benchmarks/opti_memory_bench_report.md`

### Design Rule Compilation

Compiled from claim and artifact metrics by `DesignRuleManager`.

Columns:

- Rule ID
- Status
- Confidence
- Statement
- Supported By
- Contradicted By

### Claim Contradiction

Contradicted claims must keep their evidence edge rather than being hidden.

Columns:

- Claim ID
- Status
- Claim
- Contradicting Artifact
- Metric
- Value
- Score

### Unsupported Claim Rate

Computed as:

```text
unsupported_claim_count / total_claim_count
```

## Phase 6 Mock-Real Alignment

Generate matched baselines:

```bash
python -m optiresearch.cli run-baselines --backend mock_deeplens --objective "Design depth-invariant and spectrally discriminative EDOF-HSI encoder"
MPLCONFIGDIR=workspace/mplconfig .venv-deeplens/bin/python -m optiresearch.cli run-baselines --backend deeplens --objective "Design depth-invariant and spectrally discriminative EDOF-HSI encoder"
```

Compare backends:

```bash
python -m optiresearch.cli compare-backends --left mock_deeplens --right deeplens
```

Outputs:

- `workspace/reports/backend_alignment_mock_vs_deeplens.json`
- `workspace/reports/backend_alignment_mock_vs_deeplens.md`

Alignment table columns:

- Encoder
- Mock and DeepLens depth planes
- Mock and DeepLens wavelength bands
- PSF depth similarity
- Spectral separability
- MTF mean
- Energy efficiency
- Joint score
- Backend capability level
- Encoder behavior realized

Evidence caveat:

```text
Current DeepLens backend validates adapter integration and artifact/evidence flow, not full encoder-specific optical behavior.
```

## Phase 8 Semi-Native And LLM Policy

Phase 8 adds LLM-assisted planning and review. LLM output is not evidence. It can draft plans, caveats, and paper text, but final claims still require artifact-backed `ClaimEvidence`.

DeepLens Phase 8 adds `semi_native` realization. Semi-native means part of the behavior uses DeepLens native lens-side or PSF generation mechanisms. It is not native optimized optical design.

Report:

## Phase 10 Optical-Sensitive HSI Reconstruction

Phase 10 makes the reconstruction benchmark sensitive to encoder PSF differences.

Tables should report:

- PSNR, SSIM, SAM, ERGAS, worst-depth SAM
- Reconstruction score: `PSNR - 5*SAM - 0.02*ERGAS`
- Coding strength, depth stability score, spectral separability score
- Ranking (1-5)
- Evidence level

New features:

- `mixed_materials` dataset pattern (default) with K=6 material signatures;
- `depth_spectral_coded` forward mode (default) using PSF-derived optical features;
- `OpticalFeatureExtractor` computing per-band and encoder-level features;
- `OpticalConditionedLinearReconstructor` using band-dependent spatial basis;
- `TinyCNNReconstructor` optional backend (torch required);
- Reconstruction ranking claims in ClaimEvidence.

Allowed claims:

- "controlled chromatic EDOF improves synthetic HSI reconstruction under mock setting" (only if baseline comparison shows higher reconstruction score vs conventional);
- "all encoders perform identically in HSI reconstruction" (contradicted when baseline shows metric variation).

Not allowed claims:

- "controlled chromatic EDOF is best for real HSI reconstruction";
- Any claim presenting synthetic mock-backed results as real HSI performance;
- Any claim presenting mock backend results as DeepLens native results.

Current limits:

- dataset is synthetic (no real HSI datasets);
- forward model is an evaluation proxy, not a physical sensor model;
- reconstructor is a linear baseline, not a final network;
- rankings are for system verification and method prototyping only.

Export:

```bash
python -m optiresearch.cli export-phase10-report
```

Output:

- `workspace/reports/phase10_optical_sensitive_hsi_report.md`

## Phase 11 Dataset/Reconstructor Matrix

Phase 11 introduces a matrix protocol for checking whether encoder ranking changes across dataset source and reconstructor.

Required matrix columns:

- dataset
- backend
- encoder
- reconstructor
- forward mode
- PSNR, SSIM, SAM, ERGAS, worst-depth SAM
- reconstruction score
- rank within group
- evidence level
- caveat

Allowed claims:

- "controlled chromatic EDOF improves synthetic HSI reconstruction with tiny CNN" only when the synthetic + tiny_cnn matrix row ranks controlled chromatic EDOF ahead of conventional;
- "achromatic remains best across all reconstructors" only when every available reconstructor ranks achromatic first;
- "chromatic coding benefits require stronger reconstruction network" only when linear ranking favors achromatic and an available stronger network improves chromatic or controlled chromatic ranking.

Not allowed claims:

- synthetic mock results as real HSI performance;
- public/local dataset plus mock optical encoder as real camera validation;
- DeepLens adapter_proxy as native physical validation.

Report:

```bash
python -m optiresearch.cli export-phase11-report
```

Output:

- `workspace/reports/phase11_hsi_network_dataset_report.md`
